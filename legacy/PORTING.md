# Porting record

This file says what happened to each test file of the old tree in the rewrite. A file is ported, covered by a new test, or dropped with a reason. A test that names a past regression is never dropped. `REWRITE.md` has the rule.

The record was taken at commit `b62e59d` of the `rewrite` branch. A test added after that commit is not in it. Every new test that a row names was checked to exist at that commit.

## Summary

The old tree has 314 test files. Each has one row in the [inventory](#inventory).

| Result | Files | Meaning |
|---|---|---|
| Ported | 80 | The old tests have direct counterparts. |
| Ported in part | 49 | Some old tests have counterparts. The row says which do not, and why. |
| Covered | 65 | No direct counterpart. A new unit test, command test, golden file, schema, or parity scenario checks the same behaviour. |
| Covered in part | 88 | As above, for a part of the file. |
| Dropped | 32 | Nothing replaces it. The row gives the reason: a removed feature, code that the new design does not have, or a test helper that is gone. |

## Regressions with no new test

Each row is an old test that names a past bug, for a behaviour that still applies to the new CLI, where no new test covers that behaviour. 93 rows, in four groups. When the record was taken, nothing here was fixed or written. The 9 rows of the first group were fixed after that; the other rows are for the owner to decide.
